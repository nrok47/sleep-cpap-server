# ระบบบริการตรวจการนอนหลับและติดตาม CPAP (ติดตั้งเองในโรงพยาบาล)

เว็บแอปสำหรับโรงพยาบาลศูนย์อนามัยที่ 10 อุบลราชธานี

- **หน้าสาธารณะ (ไม่ต้องล็อกอิน):** ผู้รับบริการทำแบบคัดกรอง STOP-BANG / ESS แล้วส่งชื่อ เบอร์โทร ช่วงเวลาที่สะดวก เข้าทะเบียนให้เจ้าหน้าที่โทรกลับ
- **เจ้าหน้าที่ (ล็อกอินด้วยบัญชีรายบุคคล):** ทะเบียนเคส ส่งต่องาน ใบประเมินก่อนตรวจ ปฏิทินนัด Sleep test (2 ห้อง) กรอกแทนผู้รับบริการ แก้ไข/ลบเคส
- **ผู้ดูแลระบบ:** จัดการผู้ใช้ และดูบันทึกการใช้งาน (ใครเข้าสู่ระบบ เปิดดู สร้าง แก้ไข ลบเคส เวลาใด)

ไม่ต้องติดตั้งไลบรารีเพิ่ม (ไม่มี `npm install`) ใช้ฐานข้อมูล SQLite ที่มากับ Node.js

## ความต้องการ
- Node.js **22.13 ขึ้นไป** (แนะนำรุ่น LTS ล่าสุด)
- เซิร์ฟเวอร์ Linux หรือ Windows ที่ฝ่าย IT ดูแล

## เริ่มใช้งาน
```bash
cd sleep-cpap-server
ADMIN_USER=admin ADMIN_PASS='ตั้งรหัสผ่านที่เดายาก' CLINIC_PHONE=045-xxxxxx node server.js
```
เปิดเบราว์เซอร์ที่ `http://localhost:3000`

ครั้งแรกระบบสร้างบัญชีผู้ดูแลระบบให้ ถ้าไม่ได้กำหนด `ADMIN_PASS` ระบบจะสุ่มรหัสผ่านและแสดงในหน้าจอ **เพียงครั้งเดียว** ให้จดไว้ จากนั้นเข้าแท็บ "ผู้ใช้งานและบันทึกการใช้งาน" เพื่อเพิ่มบัญชีเจ้าหน้าที่รายบุคคลและรีเซ็ตรหัสผ่าน

## ตัวแปรสภาพแวดล้อม
| ตัวแปร | ค่าเริ่มต้น | คำอธิบาย |
|---|---|---|
| `PORT` | 3000 | พอร์ต |
| `HOST` | 127.0.0.1 | ที่อยู่รับการเชื่อมต่อ (ใช้ 127.0.0.1 เมื่ออยู่หลัง nginx) |
| `DATA_DIR` | ./data | โฟลเดอร์เก็บฐานข้อมูล |
| `COOKIE_SECURE` | (ปิด) | ตั้งเป็น `1` เมื่อใช้ HTTPS |
| `TRUST_PROXY` | (ปิด) | ตั้งเป็น `1` เมื่ออยู่หลัง reverse proxy เพื่อให้จำกัดความถี่ตาม IP จริง |
| `CLINIC_PHONE` | ว่าง | เบอร์คลินิกที่แสดงในหน้าสาธารณะ |
| `SESSION_HOURS` | 12 | อายุการล็อกอินของเจ้าหน้าที่ |
| `ADMIN_USER` / `ADMIN_PASS` | admin / สุ่ม | ใช้เฉพาะตอนสร้างบัญชีแรก |
| `TZ_NAME` | Asia/Bangkok | เขตเวลาสำหรับวันที่ที่เซิร์ฟเวอร์สร้าง |

## ติดตั้งใช้งานจริง (แนะนำ)
1. **ต้องใช้ HTTPS** เพราะหน้าสาธารณะส่งชื่อและเบอร์โทร ดูตัวอย่าง `nginx.conf.sample` และตั้ง `COOKIE_SECURE=1 TRUST_PROXY=1 HOST=127.0.0.1`
2. ให้ระบบรันเป็นบริการ ดูตัวอย่าง `sleep-cpap.service` (systemd)
3. **สำรองข้อมูล:** หยุดบริการแล้วคัดลอกโฟลเดอร์ `data/` (หรือใช้ `sqlite3 data/sleepclinic.db ".backup backup.db"`) ตั้งเวลาสำรองประจำและทดสอบกู้คืน
4. จำกัดสิทธิ์โฟลเดอร์ `data/` ให้เฉพาะบัญชีที่รันบริการ

## ความปลอดภัยที่มีให้แล้ว
- รหัสผ่านเก็บแบบ scrypt, เซสชันเป็น cookie HttpOnly + SameSite=Strict
- จำกัดการล็อกอินผิด (ล็อก 15 นาที) และจำกัดการส่งคำขอสาธารณะต่อ IP (10 ครั้ง/ชั่วโมง) พร้อมช่องดักบอท และกันส่งซ้ำ
- ผู้ส่งสาธารณะเขียนได้เฉพาะ "สร้างคำขอใหม่" ไม่สามารถอ่าน แก้ไข หรือลบข้อมูลได้
- บันทึกการใช้งาน (audit log) ผู้ดูแลระบบดูได้ในระบบ

## สิ่งที่โรงพยาบาลต้องตัดสินใจเอง
- ฐานกฎหมายและประกาศความเป็นส่วนตัวของข้อมูลสุขภาพ (ข้อมูลอ่อนไหว) ก่อนเปิดใช้จริง
- ระยะเวลาเก็บข้อมูล และขั้นตอนลบข้อมูลตามคำขอ
- การเชื่อมกับ HIS/HN (เวอร์ชันนี้กรอก HN ด้วยมือ)
- การตรวจความปลอดภัยโดยฝ่าย IT/ผู้รับผิดชอบด้านข้อมูลส่วนบุคคลก่อนเปิดจริง

## ข้อจำกัดของเวอร์ชันนี้
- รันเซิร์ฟเวอร์ได้ครั้งละ 1 ตัว (SQLite) หากเจ้าหน้าที่ 2 คนแก้เคสเดียวกันพร้อมกัน ผู้บันทึกทีหลังทับ
- หน้าเจ้าหน้าที่รีเฟรชข้อมูลทุก 5 วินาที
- ฟอนต์โหลดจาก Google Fonts ถ้าเครือข่ายภายในปิดอินเทอร์เน็ต ระบบจะใช้ฟอนต์ของเครื่องแทน
- เกณฑ์แปลผลคะแนนและรายการสิทธิ์ ควรให้แพทย์/ผู้รับผิดชอบรับรองก่อนใช้
